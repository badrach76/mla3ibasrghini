# منصة ملاعب السرغيني — نسخة تجريبية متعددة الصفحات

## الملفات
- `index.html`: الصفحة الرئيسية والروابط وخريطة الموقع.
- `booking.html`: طلب حجز لملعب السرغيني 1 أو 2.
- `schedule.html`: المواعيد المؤكدة.
- `register.html`, `login.html`: طلب انخراط وتسجيل دخول تجريبي.
- `member.html`, `member-profile.html`, `member-matches.html`, `member-messages.html`, `member-news.html`: صفحات فضاء المنخرط.
- `admin.html`: لوحة تجريبية لمراجعة الحجوزات والانخراط والرسائل ونشر المستجدات وتعديل الأسعار والموقع.
- `news.html`, `location.html`: المستجدات والموقع.
- `main.js`, `style.css`, `mla3ibasrghini.jpg`, `supabase_schema.sql`.

## تجربة محلية
افتح `index.html` في متصفح حديث. البيانات التجريبية تحفظ في `localStorage` على الجهاز والمتصفح نفسيهما. دخول الإدارة التجريبي: `admin` / `Admin@12345`. طلب الانخراط يحتاج إلى قبول من لوحة الإدارة قبل أن يسمح الحساب بالدخول.

## تنبيه أمني مهم
هذه نسخة واجهة تجريبية وليست نظامًا منشورًا أو آمنًا للإنتاج. كلمات المرور وبيانات المستخدمين محفوظة محليًا في المتصفح؛ لا تُدخل بيانات حساسة ولا تستخدمها لحجوزات حقيقية. لا توجد مزامنة بين الأجهزة ولا إرسال رسائل/واتساب فعلي. بيانات دخول الإدارة ظاهرة في الملفات ويجب حذفها قبل أي نشر عام.

## الربط بالإنتاج
1. أنشئ مشروع Supabase واستخدم المصادقة الرسمية `Supabase Auth`، ولا تخزن كلمات المرور في جدول أو `localStorage`.
2. راجع `supabase_schema.sql`، وأضف سياسات RLS محددة للمنخرط والإدارة قبل فتح عمليات الكتابة.
3. نفّذ تأكيد الحجز ومنع تداخل الفترات على الخادم داخل معاملة ذرية، لا في JavaScript فقط.
4. عيّن دور الإدارة عبر آلية موثوقة؛ لا تعتمد على قيمة في المتصفح.
5. اختبر كل صلاحية وتزامن الحجوزات قبل رفع المشروع إلى GitHub وربطه بـ Vercel.
6. مواقيت الصلاة ليست مستوردة تلقائيًا في هذه النسخة؛ اعتمد مصدرًا محليًا موثوقًا قبل تطبيق قواعد الجدولة.
